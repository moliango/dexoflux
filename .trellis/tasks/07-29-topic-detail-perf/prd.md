# 话题详情首屏与长帖流畅

## Goal

缩短进帖可交互时间，降低长帖滚动卡顿与高度跳动，减少不必要的整表 `reloadData`。

## Confirmed Facts

- `TopicDetailViewController` 与 `PostNativeCell` 体量极大。
- 存在多次 `tableView.reloadData()`。
- 原生块渲染（CookedHTML + NativeContent）路径复杂，图片异步回写易触发高度变化。

## Requirements（细拆）

### B1 首屏

- 定义“首屏可交互”：标题/楼层列表至少首屏 cell 完成布局，可滚动。
- 记录并优化：进帖到首屏可交互的主要等待（API / 解析 / 图片 / 主线程布局）。
- 首屏优先渲染可见楼层，不阻塞于全帖所有图片完成。

### B2 高度与滚动

- `estimatedHeight` 与真实高度偏差导致的跳动可控（图片加载后允许局部 invalidate，避免整表闪）。
- 快速滑动时离屏重图/GIF 策略不拖垮主线程（沿用或收紧现有 pause 逻辑）。
- 嵌套回复开启时排序/缩进不导致错误复用错乱。

### B3 更新局部化

- 点赞/书签/编辑保存/回复成功后，优先单 cell 或差量更新，避免无条件整页 reload + 跳顶。
- 明确必须全量 reload 的场景列表（主题切换、楼层结构剧变等）。

### B4 内存

- 长帖（例如 100+ 楼）滑动往返不明显泄漏（Instruments 抽查，不设死指标也可先定性）。
- cell 复用取消进行中的图片任务。

### B5 测试与验收

- 回归：打开主帖、跳楼、回复、编辑、分享入口仍在。
- 增加/强化与高度或更新路径相关的单测（能测的测，测不了的写手动脚本）。

## Acceptance Criteria

- [ ] 典型图文帖进帖后，首屏可滚动不需等全部图片。
- [ ] 长帖滑动无明显整表闪白/回跳。
- [ ] 编辑/书签等操作后不无故跳回顶部。
- [ ] cell 复用不串内容（作者/正文/图）。
- [ ] build 通过；关键路径手动 checklist 通过。

## Out Of Scope

- 详情页视觉大改版、WebView 全量替代原生。
- 分享图功能本身（已有独立改动）。
